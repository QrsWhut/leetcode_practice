# Hot100 题库整理设计

**目标**

将 `LeetCode_Hot100_Java_Solution` 仓库中的 Markdown 题目文档整理到
`src/main/java/com/rsqu/leetcode/hot100` 目录下，形成与现有 `lcci` 风格一致的答题目录。
每道题创建独立目录，目录内包含 `README.md` 和一个可直接开写的 Java 模板类。

**现状**

当前仓库中的 `lcci` 目录采用“每题一个目录”的组织方式。每个题目目录通常包含：

- `README.md`
- 一个 Java 类文件

该结构已经与当前练习习惯兼容，因此 `hot100` 复用相同的目录分层。

**设计方案**

采用如下目录结构：

`src/main/java/com/rsqu/leetcode/hot100/p0001_two_sum/`

目录内包含：

- `README.md`
- `Hot1000001TwoSum.java`

其中：

- 目录名使用 `p` + 四位题号 + 下划线英文短名
- 类名使用 `Hot100` + 四位题号 + UpperCamelCase 题目名
- 包名使用 `com.rsqu.leetcode.hot100.<目录名>`

**模板策略**

普通题统一生成以下骨架：

- 类注释提示题目说明见当前目录 `README.md`
- 一个 `solution` 占位方法
- 一个空的 `main` 方法

设计题、数据结构题、缓存题等无法稳定推断签名的题目，生成保守模板：

- 保留类和 `main` 方法
- 写明中文 TODO，提示根据 `README.md` 手动补齐方法签名与测试样例

**文件来源与整理**

远端仓库中的每个 Markdown 文件视为一道题。整理时优先从文件名中解析：

- 题号
- 英文短名

若文件名格式不稳定，则回退到题目标题辅助解析；若仍无法解析，则使用稳定顺序编号，确保目录可生成且不冲突。

**约束**

- 所有新增注释使用中文
- 新增文件统一使用 UTF-8 编码
- 不修改现有 `lcci`、`lcof`、`lcof2` 目录
- 以“先可用、后补精细 main 示例”为原则，本次不强行从 Markdown 自动抽取示例填充 `main`

**验证方式**

- 验证 `hot100` 目录已创建
- 验证 Markdown 文件已按题目拆分进入独立目录
- 抽样验证生成的包名、目录名、类名一致
- 抽样执行目录与文件统计，确认数量基本匹配远端 Markdown 题目数量
